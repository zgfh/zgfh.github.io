# CNCF 项目生态

## 我关注什么

我关注 CNCF 生态中与容器、云原生基础设施和平台工程相关的项目变化，尤其是项目的新版本、功能变更、修复内容以及可能影响使用和升级的兼容性信息。

## 信息来源

主要来源是各项目在 GitHub 上的官方仓库及其 Releases 页面。GitHub Release 是项目维护者对一个版本的正式发布记录，通常包含版本号、变更内容、修复项、依赖升级和相关链接。

## 获取方式

通过程序定期抓取已关注项目的 GitHub Release 变化，识别新增版本，并提取对应的发布说明。这样不需要逐个访问项目仓库，也能持续获得项目的更新信息。

## 整理方式

抓取到的内容会按项目归档到 CNCF 目录下：

- 项目列表和项目目录用于组织不同的 CNCF 项目；
- 每个项目的 `releasenote/` 目录保存对应版本的发布说明；
- `changelog/` 目录保存程序生成的项目变化汇总；
- 项目目录下的手写文章用于补充项目介绍、安装、配置和常见问题。

目前这些内容以自动生成为主，主要用于快速了解项目近期变化。遇到值得深入研究的版本或功能，再结合官方文档、源码和实际环境进行进一步验证。

## 关注价值

这种方式把“主动搜索信息”变成“持续接收变化”，帮助我快速发现：

- 哪些项目发布了新版本；
- 新版本增加了哪些功能或修复了哪些问题；
- 依赖组件和兼容性发生了什么变化；
- 哪些更新值得进一步阅读、验证或应用到实际环境。

因此，CNCF 这里更像是一份持续更新的技术情报入口，而不是对每个 Release 的完整翻译或评价。
