## 前言

在[《一文看懂现代半导体存储芯片全景图谱》](https://mp.weixin.qq.com/s?__biz=MzYzMjkxMTQxNg==&mid=2247484097&idx=1&sn=e7782be97d0ea16133ccb6817dbaaacf&scene=21#wechat_redirect)中，我们从宏观视角梳理了存储金字塔：SRAM、DRAM、Flash 如何在速度、容量与成本间取得平衡。那么，当这些存储单元被集成到一颗芯片中，它们是如何协同工作的？

本文以乐鑫 **ESP32-S3** 为例，拆解嵌入式存储金字塔的每一层。

## 硬件配置概览

以正点原子 ATK-MWS3S 模组（对应乐鑫 ESP32-S3-WOOM N16R8）为例，一块开发板上集成了：

| 存储器 | 容量 | 位置 | 易失性 |
|--------|------|------|--------|
| ROM | 384KB | 芯片内部 | 非易失 |
| SRAM | 512KB | 芯片内部 | 易失 |
| RTC SRAM | 16KB | 芯片内部 | Deep Sleep 保持 |
| PSRAM | 8MB | 芯片外部（SPI） | 易失 |
| Flash | 16MB | 芯片外部（SPI） | 非易失 |
| EEPROM（24C02） | 256 字节 | 芯片外部（I2C） | 非易失 |

ESP32-S3 采用哈佛结构的 Xtensa® LX7 CPU 构成双核系统，所有存储器和外设分布在 CPU 总线上。

---

## 一、ROM（384KB）—— 芯片的"BIOS"

ROM 是芯片流片时固化的掩模 ROM，**出厂即固化，用户无法修改**。里面存的是**一级引导加载程序（First-Stage Bootloader）**。

**上电流程：**

```
上电 → CPU 执行 ROM 中的一级 Bootloader
     → 初始化基本硬件（时钟、电源等）
     → 从外部 Flash 固定偏移读取二级 Bootloader 到 SRAM
     → 跳转执行二级 Bootloader
     → 加载应用固件
```

ROM 是整个软件栈最底层的**信任根（Root of Trust）**，它永远不会被误删，保证了芯片每次都能正常启动。相当于 PC 主板上固化的 BIOS —— 系统启动的"第一把火"。

> **你不需要关心它，但你需要知道它的存在。**

---

## 二、SRAM（512KB）—— 高速工作台

SRAM 位于芯片内部，与 CPU 频率完全同步，**访问零等待**。你的程序运行时，变量、堆栈、临时数据都在这里。

ESP-IDF 将 SRAM 划分为两部分：

| 区域 | 用途 | 关键场景 |
|------|------|---------|
| **IRAM**（指令 RAM） | 存放对实时性要求极高的代码 | 中断服务程序（ISR），避免 Flash XIP 的 Cache 未命中延迟 |
| **DRAM**（数据 RAM） | 系统堆（Heap）和栈（Stack） | 全局变量、静态变量、`malloc` 动态内存、RTOS 任务栈 |

**注意事项：**

- IRAM 和 DRAM **共享 512KB**，此消彼长 —— 静态分配的 DRAM 最大值随 IRAM 增大而减小。
- 注册中断时若设置了 `ESP_INTR_FLAG_IRAM`，该 ISR **必须**放在 IRAM 中。
- FreeRTOS 的所有 API 已放入 IRAM，中断中调用 FreeRTOS 专属 API 是安全的。
- 如果动态内存超过 SRAM 可用量，程序直接崩溃。

---

## 三、RTC SRAM（16KB）—— Deep Sleep 数据保险箱

RTC SRAM 是 ESP32-S3 内部最特殊的存储器，物理上位于 RTC 低功耗域，**独立电源域供电**。

当系统进入 Deep Sleep 时，主 CPU 和主 SRAM 断电，但 RTC 域保持供电，数据得以保留。

| 区域 | 容量 | 可访问者 | 典型用途 |
|------|------|---------|---------|
| **RTC FAST Memory** | 8KB | 仅 CPU | 存放唤醒存根（Wake Stub）代码 |
| **RTC SLOW Memory** | 8KB | CPU + ULP 协处理器 | ULP 程序代码、唤醒原因、传感器校准参数、累计计数器 |

> 常规运行时，RTC SRAM 与普通 SRAM 无本质区别；其价值**仅在低功耗场景下才真正显现**。

---

## 四、PSRAM（8MB）—— SRAM 的外部扩容

PSRAM（伪静态随机存取存储器）是"混血儿"：**DRAM 的大容量 + 接近 SRAM 的接口速度**。

| 对比维度 | 内部 SRAM | PSRAM |
|---------|----------|-------|
| 容量 | 512KB | 8MB+ |
| 速度 | 极快（零等待） | 较快（SPI 总线） |
| 位置 | 片内 | 片外 |
| 成本 | 高 | 低 |

**适用场景：**
- 摄像头图像帧缓冲
- 大音频缓冲区
- 解析大型 JSON 数据
- LVGL 图形库帧缓冲

当片内 512KB SRAM 不够用时，PSRAM 作为堆内存（Heap）扩展，极大扩大可用 RAM 总量。

---

## 五、EEPROM（24C02）—— 关键数据的保险箱

EEPROM 用于存储**极小量、需频繁修改、掉电不能丢失**的关键数据。

ESP32-S3 有两种 EEPROM 实现方式：

1. **外接硬件**：通过 I2C 总线连接独立 EEPROM 芯片（如 AT24C02，256 字节）
2. **软件模拟**：在 Flash 上划出一块区域，用算法模拟按字节读写（NVS）

**为什么不能直接存 Flash？**
Flash 擦除必须整块操作，且擦写寿命约 10 万次，远低于 EEPROM 的百万次级别。频繁修改的小数据放 Flash 既慢又容易写坏。

**典型存储内容：**
- 设备序列号 / 唯一 ID
- MAC 地址
- 加密密钥
- 设备激活状态标记
- 传感器校准参数

---

## 六、Flash（16MB）—— 大容量仓库

Flash 通过 SPI 总线（Octal SPI 或 Quad SPI）与 SoC 连接，是固件和文件的持久化存储。

| 存储内容 | 说明 |
|---------|------|
| 程序固件 | 编译后的 `.bin` 文件烧录在此 |
| OTA 升级包 | 新固件分区，支持回滚 |
| 文件系统（SPIFFS/LittleFS） | 网页、图片、音频等静态资源 |
| NVS（Non-Volatile Storage） | Wi-Fi 密码、设备配置等键值对 |

Flash 的特点是**容量大、断电不丢**，但写入慢，擦除必须整块操作（通常 4KB/32KB/64KB），不适合频繁修改小块数据。

## 全景对比

| 特性 | ROM | SRAM | RTC SRAM | PSRAM | EEPROM | Flash |
|------|-----|------|----------|-------|--------|-------|
| 读写性 | 只读 | 读写 | 读写 | 读写 | 读写 | 读写 |
| 易失性 | 非易失 | 易失 | Deep Sleep 保持 | 易失 | 非易失 | 非易失 |
| 速度 | 快 | **极快** | 快 | 较快 | 慢 | 慢 |
| 容量 | 384KB | 512KB | 16KB | 8MB | 256B | 16MB |
| 位置 | 片内 | 片内 | 片内 | 片外 | 片外 | 片外 |
| 角色 | 启动引导 | 程序运行 | 低功耗数据保持 | 扩展内存 | 关键参数 | 持久化存储 |

---

## 为什么不能只用一种？

- **只用 SRAM**：成本太高，断电程序全丢，无法独立工作。
- **只用 Flash**：速度太慢，CPU 无法高效执行代码，频繁写小块数据会磨损。
- **只用 EEPROM**：容量太小，连操作系统都装不下。

**嵌入式存储设计的本质是分层协作**：六种存储器各司其职，共同构建从启动到运行、从休眠到恢复的完整数据流闭环。
